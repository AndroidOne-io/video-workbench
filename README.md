# 剪辑工作台（video-workbench）

所有视频**共用**的东西都在这里：剪辑规矩、风格库、音乐音效、字体、通用代码。
每一期视频单独一个仓库（口播、素材、本期时间线代码、成片），剪完可以归档或删除，不影响这里。

## 新对话开工顺序

1. 先读 [剪辑规矩](剪辑规矩.md)：默认交付、网页制作、素材、导出、检查、提交与经验沉淀的统一入口。
2. 读这期要用的风格：`风格库/<风格名>/README.md`。**不用再逐帧看参考视频**，拆解都在里面。
3. 读 [网页预览工程](网页引擎/README.md) 和 [实现与复用指南](网页引擎/实现与复用指南.md)，再读这期视频仓库的 `README.md`。新项目用模板，已有项目沿用现有流程。
4. 用 `python3 网页引擎/init_project.py <新目录>` 建立预览工程。只有继续旧 Python 工程时才使用 `工具代码/setup.sh`，其路径约定不是网页模板的依赖。
5. 按「工作流程」一段一段剪。

## 工作方式

制作、交付和经验维护统一遵循 [剪辑规矩](剪辑规矩.md)。默认提供可编辑网页工程和浏览器预览，复用公共播放器；只有本次明确授权后才导出视频。具体素材、版本、测试和提交边界以统一规则为准。

## 浏览器导出性能经验

[渲染优化经验](浏览器视频渲染优化经验.md) 提取了另一项目的原生架构、直接编码、取帧等待和并行实测经验，并列出当前公共引擎的优化落点与验收方法。性能数字保留测试条件，不作为通用速度承诺。

## 工作流程（鹈鹕测试里摸索出来的）

1. **转写口播**：sherpa-onnx SenseVoice 出带时间的句子；关键词需要逐字时间戳时，把那一句单独切出来再识别一次（输出里有每个字的时间）。校对后存成字幕源 json。
2. **定方案**：对照分镜和口播，每一句定画面。先出几张效果图（静帧）给阿亮看方向。
3. **一段一段做**（30–45 秒一段）：写这一段的场景 → 渲染几张关键时间点的静帧拼成一张图自查（字有没有压脸、小圆窗挡没挡内容、有没有小字）→ 浏览器预览；只有用户明确要求才导出视频。
4. **配乐**：每个段落一首，口播停顿处抬升 + 重击；空灵的曲子只给空镜。
5. **混音**：整片从头混（人声分段会自动做淡入淡出），-14 LUFS。
6. **交付**：默认提供可编辑工程和浏览器预览。明确要求后导出成片；本地高清原片、导出视频和缓存不默认推送。新的通用要求和经验结论同步维护到 `剪辑规矩.md`，详细文档从那里链接。
7. **素材分层**：共享仓库保留适合协作的便携素材，本地高清放忽略目录，通过服务端映射读取；Git LFS 是否可用按当前环境核验，不沿用旧环境结论。
